Protección de secretos en proyectos indexados

Reglas de exclusión aplicadas antes de que cualquier archivo llegue a ChromaDB, a un LLM, o a un commit de git.

4 capas de defensa Python · Laravel · React Node · Google · Infra 0 secretos en RAG
Arquitectura

4 capas de exclusión en cascada

Un archivo se descarta si falla cualquiera de las capas. Solo los archivos que superan las cuatro capas se indexan en ChromaDB.

1

Directorios excluidos

Si alguna parte de la ruta pertenece a un directorio protegido, el archivo se descarta sin leer. Cubre dependencias, llaves SSH, credenciales de cloud y config de IDEs.

.aws .ssh .kube .gcloud vendor node_modules .venv .git .claude .codex __pycache__ build dist

2

Nombres de archivo sensibles

Lista de nombres exactos que nunca se indexan, independientemente de dónde estén. Ver sección Por framework para el listado completo.

.env config.yaml auth.json .npmrc service_account.json terraform.tfvars kubeconfig …

3

Extensiones sensibles

Extensiones que siempre corresponden a material criptográfico o estado de infraestructura.

.pem .key .p12 .pfx .cer .crt .tfstate .tfvars .plist

4

Detección por contenido (regex)

Si el archivo pasó las capas anteriores, se lee su texto y se buscan patrones de API keys, tokens hex en URLs, bloques PEM, etc. Ver sección Patrones.

Doble cobertura: Las mismas reglas aplican tanto al indexado RAG (ChromaDB) como al versionado (Git). Un archivo excluido de RAG también está en .gitignore.

Detección por contenido

Patrones regex de secretos

Última capa de defensa: si un archivo pasa los filtros de nombre y extensión, su contenido se analiza buscando estos patrones. Si hay match, el archivo se descarta sin indexar.

PatrónQué detectaEjemplo
sk-ant-[A-Za-z0-9\-_]{20,} Anthropic API key sk-ant-api03-…
sk-[A-Za-z0-9]{30,} OpenAI API key sk-proj-…
APP_USR-[A-Za-z0-9\-]{10,} MercadoPago Access Token / Public Key APP_USR-1234…
token\s*=\s*[a-f0-9]{32,} Token hex en URL o .env (ej. ArtisanWebRunner) ?token=6c0c53c4…
-----BEGIN (RSA|EC|OPENSSH|PGP) PRIVATE KEY Bloque PEM de clave privada -----BEGIN RSA PRIVATE KEY-----
Limitación: Los patrones son best-effort. Un token con nombre no estándar (ej. MY_CUSTOM_SECRET=xyz) no será detectado a menos que coincida con los patrones de arriba. La regla de oro: nunca escribas valores reales en documentación de deploy — usá placeholders como <TOKEN_AQUI>.

Código fuente (rag.py)

Python orchestrator/rag.py 
_SECRET_PATTERN = re.compile(
    r"(?i)("
    r"sk-ant-[A-Za-z0-9\-_]{20,}"               # Anthropic
    r"|sk-[A-Za-z0-9]{30,}"                      # OpenAI
    r"|APP_USR-[A-Za-z0-9\-]{10,}"               # MercadoPago
    r"|token\s*=\s*[a-f0-9]{32,}"               # token=<hex> en URLs (genérico)
    r"|-----BEGIN\s+(?:RSA |EC |OPENSSH |PGP )PRIVATE KEY"
    r")"
)
Respuesta a incidentes

Qué hacer si un secreto quedó expuesto

Regla principal: Asumí que el secreto fue comprometido desde el momento en que apareció en un lugar incorrecto. Rotalo aunque no haya evidencia de uso malicioso.

1 — Revocar el secreto

Cada proveedor tiene su portal de revocación:

  • Anthropic — console.anthropic.com/settings/keys
  • OpenAI — platform.openai.com/api-keys
  • DeepSeek — panel de la cuenta DeepSeek
  • MercadoPago — dashboard de la cuenta → Credenciales
  • Laravel ArtisanWebRunner — cambiar ARTISAN_WEB_TOKEN en .env del servidor
  • npm / GitHub — Settings → Developer Settings → Personal access tokens
  • Google / Firebase — IAM → Service Accounts → deshabilitar / generar nueva clave

2 — Limpiar el historial

Si el secreto llegó a un commit de git:

bash 
# Opción A — reescribir historia con git-filter-repo (recomendado)
pip install git-filter-repo
git filter-repo --path archivo-con-secreto --invert-paths

# Opción B — BFG Repo Cleaner
bfg --delete-files archivo-con-secreto
git reflog expire --expire=now --all
git gc --prune=now --aggressive
git push --force

3 — Limpiar ChromaDB

Si el secreto fue indexado en el RAG del orquestador, eliminá los chunks manualmente y re-indexá sin el archivo comprometido:

bash 
# Reindexar el proyecto (el archivo con secreto ahora es detectado y omitido)
ai-orchestrator index-docs --project mi-proyecto

# O desde el dashboard: Inspector → Seleccionar proyecto → Indexar docs

4 — Redactar la documentación

Reemplazá el valor real por un placeholder en el archivo fuente:

diff 
- $URL = "https://ejemplo.cl/artisan?token=6c0c53c4VALOR_REAL"
+ $URL = "https://ejemplo.cl/artisan?token=<ARTISAN_WEB_TOKEN>"
Después de rotar: El nuevo token no estará en ningún archivo de documentación. Guardalo en tu gestor de contraseñas o en variables de entorno del CI/CD, nunca en texto plano en el repo.
