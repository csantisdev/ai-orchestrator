Orquestador local de agentes IA

Rutea tareas entre Claude, OpenAI y DeepSeek según el contexto del proyecto, con tracking de costo en tiempo real y dashboard web.

Claude · OpenAI · DeepSeek Ruteo semántico SQLite + ChromaDB Dashboard SSE
Alcances

¿Qué hace el orquestador?

Un proceso local que actúa como intermediario inteligente entre tu código y múltiples proveedores de IA. Analiza cada tarea, decide a qué modelo mandarla, registra la respuesta y muestra todo en un panel web.

🧭

Ruteo inteligente

Un modelo liviano (DeepSeek Flash) analiza la tarea y el contexto del proyecto para decidir Claude, OpenAI o DeepSeek — sin hardcodear.

💰

Control de costos

Cada run registra tokens de entrada, salida y cache. El costo en USD se calcula con la tabla de precios de config.yaml y se visualiza en el dashboard.

🧠

Memoria RAG

ChromaDB indexa la documentación de cada proyecto y las respuestas previas. Cada nueva tarea recupera contexto semántico relevante antes de llamar al modelo.

📊

Dashboard en vivo

Panel web con Server-Sent Events. Las filas aparecen en tiempo real sin recargar la página. Incluye gauge de presupuesto, filtros y panel de detalle.

🔍

Inspector DB

Vista integrada del estado interno: colecciones de ChromaDB con conteos por proyecto, tablas de SQLite y registro de proyectos con acciones de indexación.

📋

Contextos y pasos

Flujos estructurados multi-paso con alineación de checkpoints y registro de tool calls. El router puede respetar el provider definido para cada paso.

⚡

Barra de actividad

Spans en tiempo real que muestran qué está haciendo el servidor: Router, RAG retrieval, API call, indexación — con duración de cada operación.

🔄

Sync Claude Code

Importa sesiones del historial de Claude Code al DB del orquestador. Puede ejecutarse automáticamente vía hook Stop de Claude Code.

Fuera del alcance

  • No es un proxy de API — el proceso debe estar corriendo localmente
  • No orquesta agentes en paralelo — una tarea a la vez por run
  • No gestiona el historial de conversación — cada run es stateless salvo el contexto RAG
Diseño

Arquitectura del sistema

Capas principales

CLI / HTTP Server  (cli.py · Typer + BaseHTTPRequestHandler)
    │
    ├── Router            (router.py)
    │       Analiza tarea + context.yaml + keyword_hints
    │       Llama a DeepSeek Flash para decidir provider
    │       Enforce de step.provider si hay contexto activo
    │
    ├── RAG               (rag.py · ChromaDB / FTS5 fallback)
    │       retrieve_docs()     — chunks del código/docs del proyecto
    │       retrieve_responses() — respuestas previas similares
    │       build_context_block() — bloque de contexto para el system prompt
    │
    ├── Providers         (providers/)
    │       claude.py   → Anthropic API (claude-sonnet-4-6 / opus)
    │       openai.py   → OpenAI API   (gpt-4o)
    │       deepseek.py → DeepSeek API (deepseek-v4-flash / pro)
    │
    ├── DB                (db.py · SQLite WAL)
    │       runs, contexts, steps, chunks, alignments, tool_calls
    │       FTS5 virtual table sobre runs para búsqueda full-text
    │
    ├── SSE Bus           (sse.py)
    │       BUS.publish(event, data) → todas las conexiones /events
    │       Eventos: run_started, run_done, run_failed, trace, budget_warning
    │
    └── Dashboard         (dashboard.py)
            HTML generado server-side con f-strings
            JS vanilla — fetch, SSE, template literals

Base de datos SQLite

TablaContenidoClave foránea
runsCada llamada a un proveedor. Tokens, costo, duración, respuesta completa.step_id → steps
contextsFlujos de trabajo multi-paso (título, descripción, estado).—
stepsPasos dentro de un contexto. Provider sugerido, orden, estado.context_id → contexts
chunksRegistro de archivos indexados por RAG (proyecto, path, cantidad de chunks).—
alignmentsCheckpoints de alineación confirmados por el agente.step_id → steps
tool_callsHerramientas invocadas durante un paso (nombre, input, output, duración).step_id → steps

ChromaDB — colecciones

ColecciónContenidoMetadata
docsChunks de archivos .md, .py, .yaml del proyecto.project, source, chunk_idx
responsesRespuestas previas de los modelos, para recuperar contexto similar.project, run_id
runsResúmenes de runs para el router de similitud semántica.project, provider
Fallback automático: Si ChromaDB no está instalado, el router usa FTS5 (SQLite full-text search). La diferencia es que FTS5 hace matching de keywords exactas; ChromaDB hace similitud semántica por embeddings. El resto del sistema funciona igual.
Herramientas

CLI y Dashboard

Gestión de proyectos

# Registrar un proyecto
ai-orchestrator add mi-proyecto --path "C:\ruta\al\proyecto"

# Listar proyectos registrados
ai-orchestrator list

# Quitar del índice
ai-orchestrator remove mi-proyecto

Ejecutar tareas

# Router decide el proveedor automáticamente
ai-orchestrator run --project mi-proyecto --task "revisar el endpoint de login"

# Forzar proveedor específico
ai-orchestrator run --project mi-proyecto --task "..." --model claude

# Modo investigación (Claude Opus)
ai-orchestrator run --project mi-proyecto --task "..." --research

Dashboard web

# Lanza el panel en http://127.0.0.1:8080
ai-orchestrator serve

# Puerto alternativo, sin abrir el browser
ai-orchestrator serve --port 9090 --no-open

El dashboard tiene dos pestañas:

PestañaContenido
DashboardTabla de runs en tiempo real (SSE), formulario de nueva tarea, panel de detalle, gauge de presupuesto diario, barra de actividad en tiempo real.
InspectorEstado interno del sistema: tablas SQLite (conteos + últimos registros), colecciones ChromaDB con breakdown por proyecto, registro y acciones de indexación.

Indexación RAG

# Indexar archivos de un proyecto en ChromaDB
ai-orchestrator index-docs mi-proyecto

# También disponible desde el Inspector del dashboard
Sin costo de IA: La indexación usa embeddings locales de ChromaDB (all-MiniLM-L6-v2), no llama a ningún proveedor externo. El único costo ocurre al recuperar contexto durante un run.

Historial

# Últimos 20 runs con costo
ai-orchestrator history

# Filtrar por proyecto
ai-orchestrator history --project mi-proyecto --last 50

Contextos y pasos

# Crear un contexto de trabajo
ai-orchestrator create-context mi-proyecto "Implementar autenticación JWT"

# Ver contextos activos
ai-orchestrator list-contexts mi-proyecto

Sync de sesiones Claude Code

# Importar sesiones nuevas al historial
ai-orchestrator sync-cc

# Silencioso (para uso en hooks)
ai-orchestrator sync-cc --quiet
Integración automática: Agregar en ~/.claude/settings.json bajo hooks.Stop para sincronizar automáticamente al cerrar cada sesión de Claude Code.

Barra de actividad

La barra fijada al fondo del dashboard muestra spans en tiempo real. Cada operación emite un evento cuando inicia (running) y cuando termina (done/error + ms). Spans disponibles:

SpanQué mide
RouterTiempo de decisión del router (llamada a DeepSeek Flash)
RAG retrievalBúsqueda semántica en ChromaDB
{provider} · APILlamada HTTP al proveedor (Claude / OpenAI / DeepSeek)
Indexar respuestaGuardado de la respuesta en ChromaDB
Inspector · SQLiteLectura de tablas para el panel Inspector
Inspector · ChromaDBConsulta de colecciones para el panel Inspector
index-docs · {proyecto}Indexación completa de un proyecto
Configuración

Archivos de configuración

~/.ai-orchestrator/config.yaml

Credenciales, modelos y presupuestos. Nunca se versiona.

providers:
  claude:
    api_key: "sk-ant-..."
    model: "claude-sonnet-4-6"
  openai:
    api_key: "sk-..."
    model: "gpt-4o"
  deepseek:
    api_key: "sk-..."
    model: "deepseek-v4-flash"

router:
  provider: "deepseek"
  fallback_provider: "claude"

pricing:
  claude-sonnet-4-6:
    input: 3.00   # USD / 1M tokens
    output: 15.00

budgets:
  default_daily_budget_usd: 5.00
  warning_threshold: 0.80  # alerta al 80%

.orchestrator/context.yaml

Por proyecto. Se versiona junto al código del proyecto.

name: mi-proyecto
stack: PHP/Laravel
description: Aplicación web con autenticación y roles
conventions:
  - Form Requests para validación
  - PSR-12

preferred_models:
  default: claude
  notes: >
    Autenticación y permisos van siempre a Claude.
    Tests y seeders pueden ir a DeepSeek.
    Refactors frontend van bien con OpenAI.

keyword_hints:
  - match: "seguridad"
    provider: claude
    weight: 3
  - match: "test"
    provider: deepseek
    weight: 2
CampoTipoDescripción
namestringNombre legible del proyecto.
stackstringStack tecnológico (ej. "PHP/Laravel", "Python/FastAPI").
conventionslistConvenciones de código que el router incluye en el contexto.
preferred_models.notesstringTexto libre con reglas de ruteo. Lo lee el router LLM directamente.
keyword_hintslistSeñales calculadas en Python antes de llamar al router. No deciden solos — son contexto adicional.
Seguridad: config.yaml, index.yaml, *.db y el directorio chroma/ están en .gitignore y nunca deben subirse a un repositorio.

python -m venv .venv
.venv\Scripts\activate

pip install chromadb
