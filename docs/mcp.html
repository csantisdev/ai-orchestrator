MCP · Model Context Protocol

Conectá tu agente al orquestador

8 herramientas para que cualquier agente IA lea el plan de trabajo, confirme alineamiento y registre su progreso en tiempo real.

JSON-RPC · stdio Claude Desktop Claude Code Cursor ChatGPT (no)
Conexión rápida

Configurar el servidor MCP

El servidor usa transporte stdio (JSON-RPC sobre stdin/stdout). Cada cliente requiere un bloque de configuración distinto.

🤖

Claude Desktop

✓ nativo

La app de escritorio de Anthropic soporta MCP de fábrica. Editá su archivo de config y reiniciá.

⌨️

Claude Code

✓ nativo

El CLI de Anthropic. Agregá el server con un comando o editando settings.json.

🖱️

Cursor

✓ nativo

Editor con agente integrado. Crea un archivo .cursor/mcp.json en el proyecto o en tu home.

💬

ChatGPT

✗ no aplica

La web de ChatGPT no soporta MCP. Usa Custom GPTs con Actions (OpenAPI spec) — protocolo distinto.

Claude Desktop

Archivo: %APPDATA%\Claude\claude_desktop_config.json (Windows) · ~/Library/Application Support/Claude/claude_desktop_config.json (macOS)

JSON claude_desktop_config.json 
{
  "mcpServers": {
    "ai-orchestrator": {
      "command": "C:\\Fuentes\\ai-orchestrator\\.venv\\Scripts\\python.exe",
      "args": ["-m", "orchestrator.mcp"],
      "cwd": "C:\\Fuentes\\ai-orchestrator"
    }
  }
}
Ruta al intérprete: Usá la ruta completa al Python del virtualenv (.venv\Scripts\python.exe) para que Claude Desktop encuentre las dependencias instaladas. Reiniciá la app después de guardar.

Claude Code (CLI)

Opción A — comando directo (se guarda en ~/.claude/settings.json):

bash 
claude mcp add ai-orchestrator -- \
  C:\Fuentes\ai-orchestrator\.venv\Scripts\python.exe \
  -m orchestrator.mcp

Opción B — editar .claude/settings.json del proyecto (ya configurado en este repo):

JSON .claude/settings.json 
{
  "mcpServers": {
    "ai-orchestrator": {
      "command": "python",
      "args": ["-m", "orchestrator.mcp"],
      "cwd": "C:\\Fuentes\\ai-orchestrator"
    }
  }
}

Referencia

Los 8 tools disponibles

Hacé click en cada tool para ver sus parámetros y el formato de respuesta.

get_context Retorna el contexto activo de un proyecto Inicio de sesión ▼

Llamalo antes de empezar a trabajar para leer el objetivo, descripción y estado actual del contexto. Confirma que el agente está alineado con el plan registrado.

ParámetroTipoDescripción
context_idintegerID exacto del contexto. Opcional si se pasa project.
projectstringAlias del proyecto. Retorna el contexto activo más reciente.
JSON — respuesta
{
  "id": 6,
  "project": "ai-orchestrator",
  "title": "Implementar pestaña Contextos",
  "description": "Separar contextos del Dashboard principal",
  "status": "active",
  "ts": "2026-06-22T00:07:29.913905+00:00"
}
list_steps Lista los pasos del contexto con su estado actual Inicio de sesión ▼

Retorna los pasos ordenados con su estado: pending · in_progress · completed · blocked · skipped. Usalo después de get_context para saber exactamente qué sigue.

ParámetroTipoDescripción
context_id*integerID del contexto a consultar.
JSON — respuesta
{
  "steps": [
    { "id": 27, "order_idx": 1, "title": "Auditar estado actual", "status": "completed" },
    { "id": 28, "order_idx": 2, "title": "Implementar mejoras",    "status": "in_progress" }
  ]
}
create_context Crea un contexto nuevo con pasos opcionales Planificación ▼

Usalo al inicio de una tarea estructurada para que el dashboard y otros agentes puedan seguir el progreso. Los pasos se pueden agregar ahora o después con add_step.

ParámetroTipoDescripción
project*stringAlias del proyecto registrado en el orquestador.
title*stringObjetivo del contexto (qué se va a hacer).
descriptionstringDetalle adicional sobre el alcance.
stepsarrayLista de {"title": "…", "provider": "claude"}.
parent_step_idintegerStep padre para anidar contextos relacionados.
add_step Agrega un paso a un contexto existente Planificación ▼

Permite extender el plan durante la ejecución cuando aparecen tareas inesperadas. Si se omite order_idx, se agrega al final.

ParámetroTipoDescripción
context_id*integerContexto al que se agrega el paso.
title*stringDescripción del paso.
providerstringclaude · deepseek · openai · vacío = auto.
order_idxintegerPosición. Si se omite, va al final.
confirm_alignment Registra un checkpoint de alineamiento antes de actuar Durante trabajo ▼

El agente declara que está en la ruta correcta antes de ejecutar una acción significativa (escribir a disco, llamar una API, hacer un commit). Si confirmed=false, registra una desviación visible en el dashboard.

ParámetroTipoDescripción
step_id*integerID del paso activo.
context_id*integerID del contexto.
agent*stringNombre del agente, ej. "claude-code".
checkpoint*stringQué se está confirmando, ej. "listo para hacer commit".
confirmedbooleanDefault true. false registra desviación.
messagestringDetalle adicional opcional.
record_tool_call Registra una herramienta que el agente invocó Logging ▼

Auditoria de qué herramientas usó el agente dentro de un paso. Visible en el detalle de contexto del dashboard y en la pestaña Inspector.

ParámetroTipoDescripción
step_id*integerID del paso activo.
context_id*integerID del contexto.
tool_name*stringNombre de la herramienta invocada, ej. "Edit".
inputobjectArgumentos pasados a la herramienta.
outputstringResultado (puede ser truncado).
statusstring"ok" · "error".
duration_msintegerTiempo de ejecución en milisegundos.
advance_step Marca el paso como completado y activa el siguiente Durante trabajo ▼

Llamalo cuando el agente termina un paso. Si no hay más pasos pendientes, el contexto queda en estado completed automáticamente. El dashboard se actualiza vía SSE.

ParámetroTipoDescripción
step_id*integerID del paso que se completó.
notesstringResumen de lo hecho (se guarda en el paso).
JSON — respuesta
{
  "completed_step_id": 28,
  "next_step": { "id": 29, "title": "Escribir tests", "status": "in_progress" },
  "context_done": false
}
skip_step Omite un paso sin ejecutarlo Durante trabajo ▼

Para pasos que resultaron irrelevantes o ya estaban resueltos. Funciona sobre pasos en estado pending o in_progress. Si estaba activo, activa el siguiente.

ParámetroTipoDescripción
step_id*integerID del paso a omitir.
reasonstringMotivo por el que se omite (se guarda en el paso).
Uso típico

Flujo de una sesión de trabajo

Secuencia recomendada de llamadas para una sesión de agente con tracking completo.

1

Leer el contexto activo

get_context(project="mi-proyecto") → obtenés context_id, título y descripción del plan.

2

Ver qué paso está activo

list_steps(context_id=6) → identificás el paso con status="in_progress" y su step_id.

3

Confirmar alineamiento antes de actuar

confirm_alignment(step_id=28, context_id=6, agent="claude-code", checkpoint="Listo para editar dashboard.py")

4

Ejecutar el trabajo y registrar cada herramienta

record_tool_call(step_id=28, context_id=6, tool_name="Edit", status="ok", duration_ms=180) — repetir por cada tool significativa.

5

Avanzar al siguiente paso

advance_step(step_id=28, notes="Implementado filtro de estado + tab Contextos") → activa el paso 3 o completa el contexto si no hay más.

Tip: El dashboard escucha el evento SSE ctx_updated y recarga la sección de contextos en tiempo real. Cada advance_step o skip_step se refleja en el panel sin recargar la página.

Sin contexto previo — crear uno desde el agente

Si no hay contexto activo para el proyecto, el agente puede crear uno directamente:

llamada MCP 
create_context(
  project = "mi-proyecto",
  title   = "Refactor capa de autenticación",
  steps   = [
    { "title": "Auditar código existente",        "provider": "claude"   },
    { "title": "Reescribir middleware JWT",         "provider": "claude"   },
    { "title": "Actualizar tests de integración",  "provider": "deepseek" }
  ]
)
Nota

¿Por qué ChatGPT no funciona?

ChatGPT web y la app móvil no soportan MCP. El protocolo MCP usa JSON-RPC sobre stdio (proceso local). ChatGPT solo puede conectarse a herramientas externas mediante el sistema de Custom GPTs / Actions, que requiere un servidor HTTP con spec OpenAPI — un protocolo completamente distinto.

Si querés exponer el orquestador a ChatGPT o a la API de OpenAI, las opciones son:

  • Wrapper HTTP — crear endpoints REST que envuelvan los tools MCP y publicar una spec OpenAPI. El orquestador ya corre un servidor HTTP; se podría extender.
  • Bridge MCP→OpenAI — proyectos como mcp-proxy traducen el protocolo en tiempo real, pero requieren configuración adicional.
  • Usar Claude Desktop o Claude Code — es el camino de menor fricción si el objetivo es integrar con un agente conversacional.
